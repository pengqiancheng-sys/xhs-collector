> 一个 Chrome 浏览器插件：把小红书或任意网页上的**标题、正文、图片、互动数据**一键收藏进你自己的**飞书多维表格**。
>
> 适合做选题库、素材库、竞品观察库——顺手一存，自动归档，不用复制粘贴。

## 它解决什么问题

你刷小红书看到好选题、好素材，想存下来。手动做的话：截图 → 打开飞书 → 建行 → 复制标题 → 复制正文 → 存图 → 上传附件 → 填来源链接……一条要一两分钟。

这个插件把它变成**点一下**：

- 正文、标题、作者、标签、发布时间、点赞/收藏/评论数，一次全抓
- 图片自动下载并上传到飞书附件字段
- 直接写进你指定的多维表格，字段随你定义

## 功能一览

| 功能 | 说明 |
|---|---|
| 🔴 小红书收藏 | 读取页面已加载的结构化数据 + DOM 解析，拿到标题、正文、图片、作者、互动数据 |
| 🌐 网页收藏 | 任意网页都能收：标题、正文、作者、描述、来源链接、缩略图 |
| 📊 飞书同步 | 文本写入多维表格，图片自动上传到附件字段 |
| 🎛️ 可视化设置 | 在设置页配置自己的飞书应用、表格、字段映射，不用改代码 |
| 🧭 配置向导 | 三步向导：建应用 → 填凭证 → 绑表格；顶部步骤条随进度自动点亮 |
| ⚡ 扫码一键授权 | 内置飞书官方应用授权协议（RFC 8628 设备授权流程）：扫码确认后**自动拿到 App ID + App Secret**，应用名和权限都已预填，全程不用手抄 |
| 🔗 扫码绑定已有应用 | 走同一套扫码流程带上 `clientID`，给已有应用**增量补权限**，不用去后台逐个勾 |
| 🏗️ 一键建表 | 新建多维表格并把 14 个字段（含单选/多选选项）一次建全，自动绑定 + 自动映射，从根上避免 `1254062` |
| 🪄 选用已有应用 | 手动方式下的兜底：已登录飞书时，插件直接读出你控制台里的应用列表，点一下自动填好 App ID |
| 🪄 一键绑定 | 粘贴多维表格完整链接，自动解析 Token、列出数据表、完成字段映射 |
| ✅ 凭证验证 | 「保存并验证凭证」会当场调一次飞书接口，确认凭证真能换到 token 才算通过 |
| 🩺 一键体检 | 6 项开工前自检：凭证 / 表格权限 / 字段覆盖 / 单选选项是否齐全，出问题会说清差在哪、怎么修 |
| 🔗 字段映射 | 收藏到的 12 个标准字段可映射到任意多维表格字段，支持「智能自动匹配」 |
| 📋 建表提示词 | 内置一键复制的提示词，交给 AI 帮你把配套多维表格建好 |
| 🚀 博主批量收录 | 在博主主页一键批量收录，自动滚动加载、后台标签页执行、不打扰你浏览 |
| 🖱️ 右键菜单 | 页面上右键即可收藏当前页 / 某个链接 / 某张图片 |
| 📤 配置导入导出 | 团队可共享字段映射模板；导出时自动剔除 App Secret |
| 🆕 版本检查 | 每 6 小时检查一次，有更新时工具栏图标显示 `NEW` 角标 + 侧边栏顶部弹提示，点一下直达更新说明 |
| 🎨 小红书风格界面 | 浅色主题 + 圆角卡片 + 品牌红 `#FF2442`，与图标视觉统一 |

**支持的浏览器**：Chrome、Edge 及其他 Chromium 内核浏览器（Manifest V3）。

## 快速开始（三步跑通）

```
① 扫码授权拿飞书应用凭证    → 设置页点「⚡ 扫码创建新应用」，用飞书 App 扫一下
② 点「🏗️ 一键建表并绑定」   → 14 个字段 + 单选选项自动建好并绑定
③ 开始收藏                  → 完成
```

**最快两条命令都不用敲**：第 ① 步是一次扫码，第 ② 步是一次点击。大约 1 分钟。

想手工来也行（老路依然保留）：用「📋 建表提示词」交给 AI 建表，或照规格手工建，
再去开放平台手动创建应用、复制凭证 —— 见第一步和第二步里的「手动方式 / 手工建表」。

## 安装

1. 拿到 `前程-灵感素材库-v4.1.2.zip`，**解压到一个固定目录**
   > ⚠️ 不要解压到桌面或下载文件夹——那些地方容易被清理，一删插件就失效了
2. 打开 Chrome → 地址栏输入 `chrome://extensions/`
3. 打开右上角 **「开发者模式」**
4. 点击 **「加载已解压的扩展程序」** → 选择第 1 步解压出来的**文件夹**
5. 浏览器工具栏出现插件图标，点击图标即可打开侧边栏

> **如果之前装过旧版本**：请先在扩展管理页「移除」旧版，再重新加载。因为插件改名会导致扩展 ID 变化，无法原地升级。

## 安装后如何更新

**先说结论：这个插件不会自动更新。** 只有从 Chrome 应用商店安装的扩展才享受自动更新；本插件是「加载已解压的扩展程序」装的，**必须手动更新**。

好消息是：**更新不会丢配置。** 你的凭证、表格绑定、字段映射都存在 Chrome 本地，按扩展 ID 归档，覆盖程序文件不影响它。

### 更新步骤（2 分钟）

1. 拿到新版 zip，右键 **「解压」**，得到一个新文件夹
2. 把新文件夹里的文件，**全部覆盖**到你最初那个插件文件夹里
   > 只覆盖 `.js / .css / .html / .json / icons/` 就够；不要动你自己额外放进去的东西
3. 打开 `chrome://extensions/`，找到本插件卡片，点一下 **刷新 ↻**
4. 卡片上的版本号变成新版 → 完成。**不用重新填凭证**

> ⚠️ **不要**点「移除」再重新加载——那样扩展 ID 会变，配置就真丢了（除非你是从 v4.0.x 换名版升上来，那种情况本来就得重装）。

### 怎么知道有没有新版

- 插件每天自动检查一次；有新版本时，**侧边栏顶部会弹出一条红色提示**，点一下直接跳到更新说明
- 也可以手动查：设置页 → **「ℹ️ 关于」** → **「检查更新」**
- 或直接看仓库的 [Releases](https://github.com/pengqiancheng-sys/xhs-collector/releases)

### 原地升级的边界情况

| 情况 | 结果 |
|---|---|
| 覆盖同一个文件夹 → 刷新 | ✅ 配置全部保留，扩展 ID 不变 |
| 换到另一个文件夹重新加载 | ⚠️ 扩展 ID 会变，相当于装了个新扩展，要重新填凭证 |
| 「移除」旧版再装新版 | ❌ 配置丢失 |
| 从 v4.0.x（改名前的旧版）升上来 | ❌ 必须移除重装，旧 ID 与新 ID 不通用 |

> 💡 想知道当前装的是哪个版本：插件图标右键 → 「管理扩展程序」，或看设置页右上角的版本号标签。

## 第一步：创建飞书自建应用

### ⚡ 最快路径：扫码一键授权（推荐，约 30 秒）

插件内置了**飞书官方的一键授权协议** —— 就是飞书 CLI 和各语言 SDK 里那个 `registerApp`，
底层是 OAuth 2.0 设备授权流程（RFC 8628）。**不需要任何后端**，凭证只落在你自己的浏览器里。

1. 打开插件设置页 → **「🔑 飞书凭证」** 标签
2. 第 1 步的卡片里二选一：
   - **「⚡ 扫码创建新应用」** —— 还没建过应用就点这个
   - **「🔗 扫码绑定已有应用」** —— 已经有应用就点这个（先在下面第 2 步填好 App ID）
3. 浏览器会打开飞书的授权页，**用飞书 App 扫一下二维码**，在确认页点确定
   - 新建：应用名、描述、头像已经帮你填好，「多维表格 + 云空间」权限也已勾好
   - 绑定：确认页会列出这次要补的权限，确认后增量生效
4. 插件在后台按飞书给的间隔轮询，**拿到凭证后自动填进第 2 步并保存** —— App ID 和 App Secret 都不用你碰

> 💡 二维码由飞书提供，有效期约 1 小时。中途关掉标签页不影响，插件会继续等你扫码。
>
> ⚠️ 如果确认页里权限没有自动勾好（这个预填能力依赖飞书的灰度开关），改用卡片下面
> 「手动方式」里的 **「📋 复制要开的权限」**，去「权限管理」搜索开通即可。
> 无论走哪条路，**开完权限都要去「版本管理与发布」创建一个版本并发布**，权限才真正生效。

### 手动方式

> 看你有没有现成的应用：
> - **没有应用** → 按下面 1～4 建一个
> - **已经有应用** → 直接跳到第 5 步，插件能帮你把 App ID 自动读出来

1. 打开 [飞书开放平台开发者后台](https://open.feishu.cn/app)。
   没登录的话，这个链接会**直接打开扫码登录页**，用飞书 App 扫一下即可；已登录就直接进控制台。
2. 点右上角 **「创建企业自建应用」**，填个名字就行。
3. 在 **「权限管理」** 里搜索并开通以下权限：

| 用途 | 需要的权限（在后台搜索关键词开通） | 权限点标识 |
|---|---|---|
| 列出数据表 / 读字段 / 建表建字段 | 多维表格 — 查看、评论、编辑和管理 | `bitable:app` |
| 上传图片素材 | 云空间 — 查看、评论、编辑和管理云空间中所有文件 | `drive:drive` |

> 简单说：**只要两个权限点 —— `bitable:app` 和 `drive:drive`**。
> 「多维表格 — 查看」是只读权限，光有它既建不了表也写不进数据，所以直接给上面的读写权限最省事。

4. ⚠️ **开通权限后，必须「创建版本并发布」**——这一步最常被漏掉，不发布权限不会生效，接口会一直返回权限不足。

5. 拿到凭证：
   - **App ID**：进应用 → 左侧 **「凭证与基础信息」**。
     想让插件自动填？保持这个页面开着，回到插件设置页点 **「🔄 读取已打开的应用」**，
     插件会把你在控制台里看到的应用列出来，点一下「填入」就好 —— 不用手抄。
   - **App Secret**：飞书默认打码，**必须点「显示」再手动复制**。
     （走一键授权那条路插件能拿到 Secret；手动这条路飞书不让任何程序读到它。）

> 🔐 `APP_SECRET` 是敏感凭证，不要发到公开群里、不要提交到代码仓库。

## 第二步：建好配套的多维表格

插件需要一张**结构特定**的多维表格才能「零配置」直接写入。

### ⚡ 最快路径：让插件直接建（推荐）

设置页第 3 步有个 **「🏗️ 一键建表并绑定」**：

- 新建一个多维表格，**14 个字段一次建全**，字段名和类型与下面表里完全一致
- 「来源平台 / 选题来源 / 状态 / 优先级」的**单选选项一并预建**，从根上消灭
  `1254062 SingleSelectFieldConvFail` 这个最常见的新手坑
- 建成后自动绑定 + 自动完成字段映射，你不用碰链接、不用挑表

> 为什么让应用自己建表？应用对自己创建的表格天然有管理权限，
> 省掉了「在飞书里把应用添加为该文档的协作者」这一步（少了它会报 `1254302 Permission denied`）。

### 或者：交给 AI 建

1. 打开插件设置页 → 切到 **「📋 建表提示词」** 标签
2. 点击 **「📋 复制提示词」**
3. 把提示词整段粘给任意 AI（或发给帮你在飞书里建表的人）
4. 按它给出的步骤操作即可

### 或者：手工建表

照这张表在多维表格里建 14 个字段，**字段名必须完全一致**：

| 字段名 | 类型 | 选项 / 说明 |
|---|---|---|
| 选题标题 | 文本 | 主字段（第一列），不可改成其他类型 |
| 多行文本 | 文本 | 正文，最长写入约 15000 字 |
| 作者/来源 | 文本 | |
| 来源平台 | **单选** | `小红书` / `网页` / `YouTube` |
| 来源链接 | 超链接 | |
| 选题来源 | **单选** | `浏览器收录` / `链接收录` / `图片收录` / `批量收录` |
| 素材图片 | 附件 | |
| 标签 | **多选** | 格式 `#标签`，无需预建选项 |
| 发布时间 | 日期 | 日期格式选 `yyyy/MM/dd HH:mm` |
| 点赞数 | 数字 | 小数位 0 |
| 收藏数 | 数字 | 小数位 0 |
| 评论数 | 数字 | 小数位 0 |
| 状态 | **单选** | `待选题` / `已选题` / `已完成` |
| 优先级 | **单选** | `高` / `中` / `低` |

> ⚠️ **加粗的单选/多选字段，选项必须预先建全。** 如果写入时选项不存在，飞书会报错
> `1254062 SingleSelectFieldConvFail`，数据写不进去。
>
> 字段名如果和上表不一致也能用，只是需要在设置页手工做一次字段映射（或用「智能自动匹配」）。

## 第三步：在插件里配置并连接

点击插件图标打开侧边栏 → 点右上角 **⚙️** 进入设置页 → 第一个标签 **「🔑 飞书凭证」**。

这个标签是一套 **三步向导**，页面顶部的 `1 建应用 → 2 填凭证 → 3 绑表格` 会随进度自动点亮。

### 第 1 步 · 建应用

**主路径 —— 扫码一键授权：**

- **「⚡ 扫码创建新应用」** —— 向飞书申请一个授权链接并自动打开。你扫码确认后，
  插件轮询拿到 App ID + App Secret，**自动填入第 2 步并保存**。
  应用名（前程-灵感素材库）、描述、头像都已预填，`bitable:app` + `drive:drive` 权限也已一并提交申请。
- **「🔗 扫码绑定已有应用」** —— 同一套扫码流程，但带上 `clientID`，用于**给已有应用增量补权限**。
  先把 App ID 填进第 2 步，再点这个。
- 扫码期间卡片上会实时显示状态和二维码剩余时间，随时可以「停止等待」或「↗ 重新打开授权页」。
- 完成后还会多出两个快捷入口：**「🛡️ 去开权限」**、**「📤 去发布版本」**。

**兜底路径 —— 手动方式（卡片里折叠着）：**

- **「🚀 打开我的飞书应用列表」** —— 直达控制台。没登录会先给你扫码登录页，已登录就直接进去。
- **「🔄 读取已打开的应用」** —— 你在控制台里点进某个应用后，回来点这个，
  插件会读出应用列表（应用名 + App ID），点一下就填进第 2 步的输入框。
- **「📋 复制要开的权限」** —— 把权限名粘进飞书的「权限管理」搜索开通。
  > ⚠️ 开通后必须去 **「版本管理与发布」** 创建一个版本并发布，权限才生效。
  > 不发布 = 接口一直报「权限不足」，这是最常见的坑，插件里也标红提醒了。

> 为什么「读取已打开的应用」不能全自动？飞书官方的「获取企业应用列表」接口本身就要求
> `tenant_access_token`，而换 token 又必须先有 App ID + Secret —— 先有鸡还是先有蛋。
> 所以那条路只能读你已登录的页面。**一键授权走的是另一套官方协议，不受这个限制。**

### 第 2 步 · 填凭证

- 填 **App ID** 和 **App Secret**（Secret 默认打码，点 👁 可查看）
  > 直接把应用详情页的链接粘进 App ID 框也行，插件会自动把里面的 `cli_xxxx` 提取出来。
- 点 **「✅ 保存并验证凭证」** —— 插件会**当场调一次飞书接口**确认凭证能不能拿到 token
  - 通过 → 顶部步骤 2 变绿，向导自动跳到第 3 步
  - 失败 → 直接告诉你错在哪（App ID 是不是 `cli_` 打头、Secret 是不是复制漏了、应用有没有发布）

### 第 3 步 · 绑表格

**主路径 —— 让插件建表：**

- 点 **「🏗️ 一键建表并绑定」** —— 插件会新建一个多维表格，把 14 个字段一次性建好
  （单选/多选的选项一并预建），然后自动绑定、自动完成字段映射。
- 建完可以直接点旁边的 **「↗ 打开新建的表格」** 去看一眼。
- 每个字段的建成结果都会回报；万一有字段没建成，会点名说清是哪几个，你再去表里手动补。

**兜底路径 —— 已经有表格了：**

- 把多维表格的**完整链接**整段粘进来，形如
  `https://xxx.feishu.cn/base/XXXXXXXX?table=tblYYYYYYYY`
- 点 **「🪄 一键绑定」** —— 插件自动解析 Token、拉取数据表列表、读到字段、完成字段映射
- 如果表里有多个数据表，点 **「📚 读取数据表列表」** 自己选一张
- 高级场景（表不在同一个租户、只想填 Token）可以展开 **「▸ 高级：手动填写 Token / Table ID」**

> 📌 用「一键建表」建出来的表格，**应用是它的创建者，天然有管理权限**，
> 所以不需要像手动建表那样再去飞书里「把应用添加为文档协作者」。

### 最后：一键体检

三样都配好了，点页面最下方的 **「🩺 一键体检」**。它会跑 6 项检查：

| 检查项 | 查什么 | 不通过会怎样 |
|---|---|---|
| 凭证已填写 | App ID / Secret 是否为空 | 收藏时提示「请先配置凭证」 |
| 凭证可用 | 能否真的换到 tenant_access_token | 全部写入失败 |
| 已绑定表格 | app_token / table_id 是否完整 | 提示「请先绑定表格」 |
| 表格可读、权限足够 | 能否读到表结构 | 报错 `1254005` / 权限不足 |
| 字段映射覆盖 | 12 个字段有几个对上了 | 对不上的字段写不进去 |
| 单选选项齐全 | 表里的选项是否包含插件要写的值 | 报错 `1254062` ← 90% 的人都栽在这 |

每项不通过都会给出**具体怎么修**。体检全绿再开始收藏，能省掉绝大部分「为什么写不进去」的来回。

> 💡 **配置可以共享给团队**：设置页「ℹ️ 关于」→「📤 导出配置」会生成一个 JSON（**不含 App Secret**），
> 别人导入后再自己填一下 Secret 即可，省去手工映射的功夫。

```text
【写入数据格式要求（供你校验字段类型是否正确）】
建完字段后，请确认这张表能接受下面这种结构的数据：

{
  "选题标题": "秋冬穿搭公式，普通人也能穿出高级感",
  "多行文本": "笔记正文内容……（最长 15000 字符）",
```

## 常见问题

### 写入报错 `1254062` / `SingleSelectFieldConvFail`

单选或多选字段的**选项不存在**。检查：

- 「来源平台」是否有 `小红书`、`网页` 两个选项
- 「选题来源」是否有 `浏览器收录`、`链接收录`、`图片收录`、`批量收录` 四个选项
- 「状态」是否有 `待选题`、`已选题`、`已完成`；「优先级」是否有 `高`、`中`、`低`

选项文字必须**逐字一致**，全角/半角、多余空格都会导致失败。

### 提示「权限不足」/ `Permission denied`

飞书应用权限**没有发布版本**。回开放平台「版本管理与发布」创建一个版本并发布，权限才会生效。

### 提示「请先配置飞书应用凭证」

设置页的凭证或表格信息没填全，或者点了「测试连接」但没保存。检查：App ID、App Secret、多维表格链接、数据表是否都选好了。

### 扫完码插件没反应 / 权限没自动勾上

分两种情况看：

- **插件一直显示「已打开飞书授权页…」** —— 先确认你在飞书的确认页上点了「确定」。
  没点确定插件会一直等（二维码有效期约 1 小时）。轮询间隔由飞书下发（默认 5 秒），
  你扫码后最多等一个间隔就会自动填入。
- **确认页里权限没有预先勾好** —— 「权限预填」这个能力依赖飞书侧的灰度开关，没开的话会被静默忽略。
  插件此时会把应用建好、凭证也照常拿到，只是权限要你去「权限管理」手动加一下：
  展开卡片下面的「手动方式」，点 **「📋 复制要开的权限」**，粘到「权限管理」搜索开通。
  加完**记得去「版本管理与发布」创建一个版本并发布**，否则接口会一直报权限不足。
  做完这些可以点卡片上的 **「📤 去发布版本」** 直达。

### 点「一键建表」报权限不足 / `1254302`

`1254302 Permission denied` 意思是调用身份缺少多维表格的高级权限。按顺序排查：

1. 应用有没有 `bitable:app`（多维表格 — 查看、评论、编辑和管理）这个**读写**权限？
   只有「多维表格 — 查看」是建不了表的。
2. 加完权限**发布版本了吗**？没发布 = 一直 403。
3. 如果这张表是**你手动建的**、不是插件建的，还需要在表格页面右上角
   「…」→「更多」→「添加文档应用」里把应用加进去。
   （用「🏗️ 一键建表并绑定」建的表格没这个问题 —— 应用是创建者，天然有权限。）

### 点「读取已打开的应用」提示找不到页面

需要先在飞书开发者后台里打开着页面。正确顺序是：

1. 设置页点 **「🚀 打开我的飞书应用列表」**（会在新标签页打开控制台）
2. 在控制台里点进你要用的那个应用
3. 回到插件的设置页，点 **「🔄 读取已打开的应用」**

如果控制台标签页后来被关掉了，自然读不到，重新打开一次即可。

### App ID 能自动填，App Secret 为什么不行

飞书的「凭证与基础信息」页面把 App Secret 默认打码，必须手动点「显示」才能看到。
插件只读页面上的文字，读不到没被渲染出来的内容；而且出于安全考虑，我们也不打算去读它。
所以 Secret 这一步只能你自己复制粘贴。

### 收藏成功但正文是空的

页面可能还没加载完。等页面正文显示出来再点收藏。如果反复出现，在「🎛️ 收藏设置」里确认 **「页面数据读取」** 和 **「页面信息解析」** 两个开关都是打开的。

### 图片没上传 / 附件字段是空的

- 确认「🎛️ 收藏设置」里 **「图片同步」** 是打开的
- 检查「最多上传图片数」是不是设得太小
- 图片是逐张串行上传的，图多会慢一些，耐心等进度走完

### 批量收录很慢

正常。默认每篇间隔 2 秒 + 页面加载时间。想快一点就把「间隔(秒)」调小（不要低于 1 秒，容易被限流）。**收录 30 篇大约需要 2 分钟。**

### 表格里出现重复记录

插件目前**不做跨次去重**——同一篇笔记收藏两次就会有两行。建议：

- 收藏前先在表格里搜一下来源链接
- 或在多维表格里加一个「自动化」，按「来源链接」做去重删除

### 收藏不了某些网站

部分网站有严格的反自动化限制，或页面结构特殊导致提取不到内容。换用右键菜单「收藏这个链接」可以至少把 URL 存进去。

### 装了新版本后插件消失了

先确认是不是**在扩展管理页点了「移除」**——移除会连同配置一起删掉。正确做法见 [安装后如何更新](#安装后如何更新)：覆盖文件 + 点刷新 ↻，不要移除。

如果是从 **v4.0.x（改名前的版本）** 升上来的：那次改过名字，扩展 ID 变了，**必须移除重装**，属于唯一例外。

### 更新后凭证还要重填吗

不用。凭证存在 Chrome 本地的 `chrome.storage.local`，按扩展 ID 归档，覆盖程序文件不影响。只有「换文件夹重新加载」或「移除重装」会丢。保险起见可以先用「📤 导出配置」备份一份（导出内容不含 App Secret）。

### 怎么确认用的是最新版

设置页 → **「ℹ️ 关于」** 标签，第一张卡片就写着当前版本号，旁边有 **「检查更新」** 按钮。插件每天也会自动查一次，有新版本时侧边栏顶部会弹红色提示，点一下直达更新说明。

### 不知道哪里配错了，怎么办

设置页「🔑 飞书凭证」标签最下方点 **「🩺 一键体检」**，6 项挨个查，不通过的直接告诉你错在哪、怎么修。比对着报错码猜快得多。

```
├── icons/              图标
├── LICENSE             MIT
└── README.md           本文件
```

**数据流**：

```
页面 → xhs-bridge（MAIN 世界拦截接口响应）
         ↓ postMessage
     page-observer（DOM 解析 + 页面识别）
         ↓ chrome.runtime.sendMessage
     background（任务队列 → 字段映射 → 飞书 API）
         ↓
     飞书多维表格（记录 + 附件）
```

**权限说明**（`manifest.json`）：

| 权限 | 用途 |
|---|---|
| `activeTab` / `tabs` | 读取当前标签页信息；打开飞书控制台 / 授权页标签、向其中查询当前应用 |
| `scripting` | 注入解析脚本 |
| `sidePanel` | 侧边栏 |
| `storage` | 保存配置与凭证 |
| `contextMenus` | 右键菜单 |
| `alarms` | 定时检查更新 |

| `host_permissions: accounts.feishu.cn` / `accounts.larksuite.com` | 一键授权：申请设备授权码并轮询换取 App ID / Secret |

**第三方依赖**：仅 `vendor/md5.min.js`（用于飞书上传素材的签名计算），已内置，无网络依赖。

## 安全说明

- **App Secret 只存在你本机的浏览器存储里**（`chrome.storage.local`），不会上传到任何第三方服务器。
- **`feishu-bridge.js` 只在 `open.feishu.cn` 上运行，且只读 DOM**：不注入任何界面、不发额外网络请求、
  不上传页面内容。它读到的只有你的应用名和 App ID（`cli_` 开头，本来就是公开标识）。
- **走「一键授权」时，App Secret 是飞书主动交给插件的**（这是飞书官方协议的既定行为），
  拿到后只写进本机 `chrome.storage.local`，不经过任何中间服务器。它来自飞书的
  `accounts.feishu.cn` 官方接口，插件没有自己的后端。
- **走「手动方式」时，App Secret 插件读不到也不去读**。飞书默认把 Secret 打码，必须你手动点「显示」再复制。
- **一键授权不经过任何第三方**：整条链路只有浏览器 ↔ `accounts.feishu.cn` ↔ `open.feishu.cn`。
  你可以打开 DevTools → Network 自行核对。
- **导出配置时自动剔除 App Secret**，导出文件可以安全地分享给同事。
- 开源仓库里**不包含任何真实的 App Secret 或表格 Token**。
- ⚠️ **不要把 App Secret 发给别人。** 拿到它的人可以读写你授权的全部多维表格。
- 本工具用于**个人素材归档与整理**。请遵守你访问的网站的服务条款，并自行确认所收藏内容的合规使用范围。

### v4.2.0

**新增：扫码一键授权，不用再手抄凭证**

用上了飞书官方的一键授权协议 —— 也就是飞书 CLI 和各语言 SDK 里那个 `registerApp`，
底层是 **OAuth 2.0 设备授权流程（RFC 8628）**。它是公开的 HTTP 协议，
插件的扩展页面又持有 `accounts.feishu.cn` 的 host 权限、不受 CORS 限制，
**所以整条链路都能在插件里跑完，不需要任何自建后端。**

  插件轮询拿到 **App ID + App Secret 并自动填入、自动保存**。
  应用名 / 描述 / 头像预填好（图标直接用仓库里的图），`bitable:app` + `drive:drive` 两个权限一并提交申请。
